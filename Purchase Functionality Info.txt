📦 Purchase & Procurement Module — Final Functional Specification
🎯 Objective

Implement a Purchase & Procurement module that allows recording of:

Vehicle purchases from OEM

Spare purchases from OEM

Spare purchases from other vendors

The module must:

Update inventory automatically

Preserve full historical pricing (no overwrite/delete)

Handle rate changes safely

Support missing part codes

Track vehicle chassis + components

Integrate with service duration rules

Enforce strict role-based access

Maintain full auditability

1️⃣ Roles & Access Control (STRICT)
Roles
Admin

Manage master data (parts, vehicles, models, service durations, vendors)

Update pricing master

Configure system

View all purchases

Dealer

Create purchases

View purchases

Cannot modify masters or pricing rules

Staff

❌ No access to purchase module

Enforcement Rules

Purchase menu visible only to Dealer & Admin

Staff cannot access backend APIs

Dealer cannot change master prices

Only Admin can modify master records

2️⃣ Purchase Creation Flow
Dealer Workflow

Select Vendor

Add items (vehicles/spares)

Add quantity

Add vehicle serials (if vehicle)

Choose “Include in Accounting” flag

Save

Mandatory Behavior

On save:

Inventory auto-updates

Purchase snapshot stored

Pricing frozen for that purchase

No master data altered

3️⃣ Price Change Handling (CRITICAL — No Data Loss)
Problem

Rates change over time.
If we update master price directly:
❌ Old purchases become incorrect
❌ Reports break
❌ Profit calculation wrong

Required Solution: Price Versioning / Snapshot System
Rules
A. Master prices must NEVER be overwritten

Instead:

Create new price entry/version

Old prices remain stored

B. Purchase must store price snapshot

When dealer selects item:

fetch current price

store that price inside purchase item

future changes must NOT affect old purchase

Functional Behavior
When price changes:

Admin:

adds new rate version

sets effective date

System:

automatically uses latest active price for new purchases only

Old purchases:

remain unchanged

Result

✔ Full history
✔ Accurate profit
✔ No overwrite
✔ Audit safe

4️⃣ Handling Price Mismatch During Purchase
Scenario

Master price = ₹100
Vendor invoice shows = ₹110

Required behavior

Dealer must be able to:

override price at purchase time

system stores overridden price only for that purchase

BUT:

master price remains unchanged

Optional Warning

System may show:
“Entered price differs from master price”

5️⃣ Missing Part Code Handling
Problem

Sometimes dealer buys a new spare/vehicle not yet in master list.

Required behavior
During purchase:

Dealer sees:
➕ “Create Temporary Item”

Dealer can:

add minimal details

continue purchase

System:

marks item as “Unverified / Temporary”

After that

Admin must:

review

convert into proper master entry

map existing purchases to that master

Rules

Dealer cannot permanently create master

Only Admin can approve/convert

6️⃣ Vehicle + Chassis + Model Linking
Requirement

Required Structure

Sales behavior

While creating sale:

“available chassis numbers for that model”

Benefits

✔ No typing errors
✔ No duplicate sales
✔ Accurate stock
✔ Faster billing
